# 构建与复现

本页讲**结构约束**：动手改之前必须知道的东西。逐条命令见 [REPRODUCE](../REPRODUCE.md)。

## 一、镜像结构概览

| 层 | 内容 | 改动方式 |
|---|---|---|
| 光盘文件系统 | ISO9660，游戏数据以大包形式存放 | 封盘时重建，不手改 |
| 资源包 | 多个按 ID 编号的资源包（如 `1200000`、`1200011`、`4002050`） | 解包 → 改成员 → 重新打包 |
| 文本 | 明文表 + 压缩条目（LZSS 类）两层并存 | 两层都要改，只改一层会出现"旧译回魂" |
| 字库 | 每个包内：图集（atlas）+ 码表/记录表（FontMap）+ slot 表 | 只改字形内容与目标记录字段 |

## 二、字库的结构约束

这些是**冻结**的，任何改动都必须先证明不动它们也能达到目的：

1. **slot 数 / 码表长度 / FontMap 结构** 保持不变。扩容会牵动引擎侧查表，代价极高。
2. **图集几何以包内 TEX0 为准**。不要相信文档里记的固定尺寸——不同包可能不同，
   历史上就是因为按固定尺寸假设，导致图集解错、字形错位。
3. **引擎只采样图集的上半区（行 0..511）**。下半区在实机上被证否，全量重做必须落在上半区。
4. **字形基线锚在 rect 底边**，不是盒顶。裁 rect 底会让整行字下移。
5. **渲染包不能猜**。一个屏幕用哪个包，必须用行为判据（逐码对照、墨迹比对）确认，
   不能靠"看起来最合适"的启发式。猜错会改错包，比不改更糟。

## 三、文本的约束

1. 译文唯一来源是 `corpus/`，不接受直接改镜像。
2. 明文层与压缩层的同一条目必须同源改写，否则会因加载路径不同而露出旧译文。
3. 半角/全角、标点与空格属于排版的一部分，改动前先确认该屏的模板规则，
   否则会出现"删行""错位""溢出"。

## 四、环境与依赖锁定

| 项 | 锁定方式 |
|---|---|
| Python | 记录主版本与次版本；脚本不使用 3.10 以下语法 |
| 依赖库 | `requirements.txt` 固定版本（待补齐） |
| 字体 | Source Han Sans SC，记录版本与文件哈希；字体文件不入库 |
| xdelta3 | 生成差分时记录版本 |
| PCSX2 | 验收记录必须写版本号 |

## 五、构建产物与命名

```text
build/
├─ extract/                 解包结果（不入库）
├─ font/                    生成的字形与字库（不入库）
├─ ace3-zh-<版本>.iso       成品镜像（不入库，不进 Release）
└─ ace3-zh-<版本>.xdelta    差分补丁（进 Release）
```

命名规则：`ace3-zh-<主>.<次>.<修订>.xdelta`，与 `CHANGELOG.md` 的版本号一致。

## 六、红线的由来

下面每条都对应一次真实踩坑，不是理论推演：

| 红线 | 踩过的坑 |
|---|---|
| 不按固定尺寸假设图集 | 图集几何按错误尺寸解析，字形整片错位 |
| 不信"第二半能采样" | 实机证否，写入下半区的字形永远不显示 |
| 不猜渲染包 | 改错包，问题没修还引入新花屏 |
| 不只改一层文本 | 压缩层残留旧译文，屏上出现前后不一致 |
| 不在满载包里腾字 | 零引用码往往是受保护类，删了会崩 |
